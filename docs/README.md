# Subcontractor Weekly Report Automation

Turn a folder of messy subcontractor timesheets into one clean, formula-driven project report in a few seconds.

All data in this repo is fake sample data generated by a script. Nothing here is a real client result.

## The problem

Every week, a project coordinator gets timesheets from several subcontractors. Each one is formatted differently:

- Different column names ("Hours", "Hrs", "Hours Worked")
- Mixed date formats
- Header rows that start on different lines
- Blank rows, TOTAL rows, duplicate entries, typos in project codes, impossible 16 hour days

Someone then spends hours copying and pasting everything into one workbook, fixing it by hand, and hoping nothing slipped through.

## What this does

Drop the files in `input/`, run one command, and get:

- **One Excel report** with five sheets: Overview, By Project, By Subcontractor, Clean Data, Exceptions
- **Live formulas.** Edit an hour or a rate in Clean Data and every total updates
- **An Exceptions sheet** that lists every problem found, which file and row it came from, and what was done about it
- **A draft weekly email** (text only, nothing is ever sent)

### What it catches

| Problem | What happens |
|---|---|
| Different column names | Mapped to a standard set |
| Header row on a different line | Detected automatically |
| Mixed date formats | Normalized |
| Rates or hours stored as text ("$52.00", "8 hrs") | Converted to numbers |
| Duplicate entries | Removed and logged |
| Fixable project codes (`p102`) | Cleaned to `P-102` |
| Unknown project codes (`P-1O2`) | Excluded and flagged |
| Missing hours | Excluded and flagged |
| Dates outside the reporting week | Kept and flagged for review |
| More than 12 hours in a day for one worker | Kept and flagged for review |
| Blank rows and TOTAL rows | Ignored |

## Quick start

Requires Python 3.10 or newer.

```bash
git clone https://github.com/AshraySikka/sub-report-automation.git
cd sub-report-automation

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python generate_samples.py       # creates 10 messy sample files in input/
python process_reports.py        # builds the report in output/
```

Open `output/weekly_project_report_2026-09-28.xlsx` in Excel and read `output/email_draft.txt`.

To use your own files, skip `generate_samples.py` and put your `.xlsx` timesheets in `input/`.

## Project structure

```
generate_samples.py   Creates 10 deliberately messy sample timesheets
process_reports.py    Reads, cleans, validates and builds the report
requirements.txt      pandas, openpyxl
input/                Timesheets go here (git-ignored)
output/               Report and email draft land here (git-ignored)
```

## Configuration

Settings live at the top of `process_reports.py`:

```python
VALID_PROJECTS = {"P-101", "P-102", "P-103"}   # accepted project codes
MAX_DAILY_HOURS = 12                           # flag anything above this per worker per day
SYNONYMS = {...}                               # column names it recognizes
```

If a new subcontractor uses a column name it doesn't know, add it to `SYNONYMS`.

## How it works

1. Scan each file for the header row and map its columns to a standard set
2. Clean dates, numbers and project codes
3. Remove duplicates and detect the reporting week
4. Validate each row and log problems to the Exceptions list
5. Write the Excel report, then replace the totals with live formulas
6. Draft the weekly email

## Known limitations

- Real client files are messier than the sample files. Expect to add column synonyms and rules per client.
- Formulas are calculated when the file is opened in Excel. Some previewers (Quick Look, email and phone viewers) may show blanks until then.
- It handles `.xlsx` only. No PDFs, scanned documents or `.xls` files yet.
- Project codes and the daily hours limit are set in code. A real deployment would move these to a config file.
- The Exceptions sheet is a log of what happened during processing, so it does not update if you edit the data afterwards.
